## 2. 来源判定规则与优先级

`derive_security_flags()` 对每个字段分别计算三态值 `True / False / None`：

1. 顶层显式字段和 `source_metadata` 同名字段必须是原生 `bool`；两者一致时作为显式来源，冲突时返回 `None`，并记录两个字段来源。
2. 明确类型标记仅识别 `ai`、`assistant`、`system`，且只确认对应属性为 `True`。
3. 显式字段与相反类型标记冲突时返回 `None`，不采用字段遍历顺序覆盖。
4. 多个类型来源同时出现不同类别（例如 `system` 与 `assistant`）时，两个安全属性均返回 `None`，来源记录为稳定的 `conflict:type_markers:...`。
5. 缺失或普通文本类型不构成可靠证据，返回 `None`；不会把普通消息推断为 `False`。
6. 字符串、数字、列表、对象等非法显式值不会进行 truthiness 或字符串转换，返回 `None` 并记录 `invalid_type:<source>`。

显式来源优先于一致的类型来源，但冲突不会静默选择显式值；来源映射 `security_flag_sources` 只记录判定依据，不伪装成原始导出字段。

## 3. 冲突与非法输入复核

新增/补充的参数化合成测试覆盖：

- `False + system`：`is_system=None`，记录显式与 system 类型冲突。
- `False + ai/assistant`：`is_ai_generated=None`，记录显式与 AI 类型冲突。
- `True + 相反类型`：返回 `None`，记录可审计冲突。
- 顶层字段与 `source_metadata` 同名字段值不一致：返回 `None`，不静默覆盖。
- `"false"`、`0`、列表、对象：均拒绝隐式转换。
- 多个类型来源相互矛盾：两个字段均 unknown，结果不依赖输入字典插入顺序。
- 多个一致类型来源：结果和来源选择稳定。

这次发现并修复的最小缺陷是：原实现只识别“同属性”类型标记，无法把 `system` 与 AI 属性的显式值冲突统一纳入冲突结果；同时原来源文本不足以审计顶层/metadata 冲突。修复仅涉及 `security_flags.py` 与其合成测试。

## 4. 适配器边界复核

`synthetic_adapter.py` 仍要求 `is_ai_generated` 和 `is_system` 两个字段都存在且为真正的 `bool`。因此：

- 任一字段为 `None`、缺失或非法类型：拒绝普通画像证据。
- 任一字段为 `True`：拒绝普通画像证据。
- 两字段为显式 `False` 仅表示通过安全标记门槛，正文类型、`content_status`、角色映射、证据 ID、引文和时序校验仍必须通过。
- 没有新增默认 `False`，没有放宽媒体、AI/system 或 unknown 的资格门槛。
